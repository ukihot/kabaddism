# カバディズム 要件定義書

v1.0 / 対象: MVP（一年分のサイクルが遊べる状態）
上位文書: [concept.md](concept.md) / 下位文書: [design.md](design.md)

---

## 1. 本書の位置づけ

企画書（concept.md）を実装可能な粒度へ落とし、**何を作るか／何を作らないか**を確定する。
実装方式は design.md で扱い、本書では規定しない。

### 1.1 前提条件（確定事項）

| 項目 | 決定 |
|---|---|
| ジャンル | 国家運営シミュレーション（スポーツ育成 × 町づくり） |
| プレイ人数 | **完全ソロ**。オンライン要素・アカウント・通信を一切持たない |
| エンジン | **Bevy 0.19.1**（Rust, edition 2024） |
| 対象OS | Windows 10/11 x86_64（主）、Linux x86_64（副） |
| 配信形態 | PC 単体実行（Steam 想定。ただし v1 は SDK 非統合） |
| 表示言語 | 日本語のみ（文言は外部データ化し、後から追加可能にする） |

### 1.2 v1 のゴール

ゲーム内時間で **1年（大会から次の大会まで）を完走できる**こと。
concept §20「最初に通す体験」1〜7 が、通しプレイで成立すること。

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| **日** | シミュレーションの最小時間単位。すべての状態更新は日単位で行う |
| **ティック** | 1日分の内部処理一巡 |
| **政策カード** | プレイヤーの唯一の能動的操作単位。実行すると所定日数だけ時間が進む |
| **地区 (District)** | 町の区画。施設・住民コホート・移動距離を持つ |
| **コホート** | 年齢層・職業・生活水準で括った住民集団。個体として追跡しない国民の表現 |
| **追跡人物 (Tracked Person)** | 個体として状態・履歴・名前を持つ人物（代表候補、指導者、地域の有力選手など） |
| **K** | 統計・会計用の価値評価単位。現金通貨ではない（concept §13） |
| **現カバ** | 店頭でのカバディ対戦による即時決済 |
| **カード** | 商品を先に受け取り、週末の町内大会でまとめて清算する決済 |
| **決済負担 (Obligation)** | カード利用により累積し、週末大会で清算すべき量。K建て |
| **利用枠 (Credit Limit)** | 世帯・コホートが持てる決済負担の上限 |
| **生活余力** | 必需品充足後に残る、可処分な時間と資源 |
| **年度** | 予算編成日から次の予算編成日まで |

## 3. 機能要件

要件IDは `FR-<領域>-<連番>`。**[必須]** は v1 必達、**[任意]** は v1 で落としてよい。

### 3.1 時間進行（FR-TIME）

| ID | 要件 |
|---|---|
| FR-TIME-01 | **[必須]** 時間は日単位で進む。1日未満の時間表現を持たない |
| FR-TIME-02 | **[必須]** 時間はプレイヤーが政策カードを実行した時のみ進む。放置で経過しない |
| FR-TIME-03 | **[必須]** 情報の閲覧・比較・人物/施設/地図の確認では日数を消費しない |
| FR-TIME-04 | **[必須]** 進行中はニュースが日付順に流れ、任意の日で中断できる |
| FR-TIME-05 | **[必須]** 進行中に**予算編成日**または**世界大会日**へ到達した場合、その日で必ず停止しイベントへ遷移する |
| FR-TIME-06 | **[必須]** 年次イベント終了後、残日数があれば進行を再開する（残日数は失われない） |
| FR-TIME-07 | **[必須]** 通常ニュース・週末町内大会・ネガティブイベントは進行を停止しない |
| FR-TIME-08 | **[必須]** 1年 = 360日（12ヶ月 × 30日）。予算編成日と世界大会日は年内の別日に固定配置する |
| FR-TIME-09 | **[必須]** 週末町内大会は7日周期で自動発生し、自動進行する |

### 3.2 政策カード（FR-POL）

| ID | 要件 |
|---|---|
| FR-POL-01 | **[必須]** カードは外部データファイルで定義し、コード変更なしに追加・調整できる |
| FR-POL-02 | **[必須]** カードは次を表示する: 進行日数／初期費用／継続費用（年額）／必要人員・施設／対象地域・集団／効果発現時期／想定される変化と不確実性 |
| FR-POL-03 | **[必須]** 実行可能条件（予算残・人員・施設・前提事業・対象の存在）を満たさないカードは実行不可とし、**不足している条件を明示**する |
| FR-POL-04 | **[必須]** カードは「決定・手続き」を表し、それが起こす**事業 (Project)** は別途の期間をかけて完成する。事業は次の政策の実行中も並行して進む |
| FR-POL-05 | **[必須]** 現状の問題に関連するカードを推奨枠に提示する。全カード一覧からも選択できる |
| FR-POL-06 | **[必須]** 制度・カードに固定の能力ボーナスを持たせない。効果は必ず「生活・事業環境の変化」を経由する（concept §21-6, §4） |
| FR-POL-07 | **[必須]** カードは俗称と大仰な公文書名の両方を持てる |
| FR-POL-08 | **[必須]** v1 のカード種は concept §11 の20枚を実装する |
| FR-POL-09 | **[任意]** カードの実行履歴を年度ごとに閲覧できる |

### 3.3 日次シミュレーション（FR-SIM）

| ID | 要件 |
|---|---|
| FR-SIM-01 | **[必須]** 1ティックは次の順で処理する: ①政策・契約・工事・育成事業の進捗 → ②生産・収支・仕事・生活・練習・回復 → ③イベント判定 → ④イベント結果の反映 → ⑤国家ステータス集計 → ⑥ニュース生成 |
| FR-SIM-02 | **[必須]** 乱数は3種に分離する: 日常変動／条件付きイベント／外部環境変化 |
| FR-SIM-03 | **[必須]** 国家ステータスへ乱数を直接加算しない。現場（人物・施設・地区）の変化を集計した結果として算出する |
| FR-SIM-04 | **[必須]** イベント抽選は**日次で**行う。政策カードの日数によって期待発生回数が歪まないこと |
| FR-SIM-05 | **[必須]** 全国平均のみでイベント判定しない。対象の地区・集団・施設の状態を参照する |
| FR-SIM-06 | **[必須]** 同一対象の同一問題を重複発生させない（進行中フラグを持つ） |
| FR-SIM-07 | **[必須]** 深刻な問題の前に予兆イベントを出す（2段階以上） |
| FR-SIM-08 | **[必須]** 外部環境の変動（天候・供給）と、それを受け止める能力を別変数として持つ |
| FR-SIM-09 | **[必須]** 数週間〜数ヶ月の観測で政策の方向性が読み取れる程度に、日次のノイズ幅を抑える |
| FR-SIM-10 | **[必須]** 問題解決後も、人物・施設に履歴を残す |

### 3.4 国民・人物（FR-POP）

| ID | 要件 |
|---|---|
| FR-POP-01 | **[必須]** 国民は**コホート**と**追跡人物**の2階層で表現する。両者は同一の時間・資源ルールで動く |
| FR-POP-02 | **[必須]** 人物の状態: 年齢／職業／世帯／受給権と生活資源／住環境・通勤／健康・栄養・疲労／練習時間・競技経験・意欲／能力・才能／所属チーム・契約／チーム利用範囲 |
| FR-POP-03 | **[必須]** 1日24時間を、睡眠・仕事・通勤・家事育児・決済活動・練習・余暇に配分する。**練習時間は余剰時間からのみ確保される** |
| FR-POP-04 | **[必須]** 疲労は練習・仕事・現カバ決済・週末大会で蓄積し、睡眠・住環境・栄養・医療で回復する |
| FR-POP-05 | **[必須]** 高疲労の継続は成長効率を下げ、負傷確率を上げる |
| FR-POP-06 | **[必須]** 能力成長は「練習時間 × 指導の質 × 才能 × コンディション」を経由する。政策から能力値への直接加算を行わない |
| FR-POP-07 | **[必須]** 追跡人物は成長・移籍・引退・負傷・離脱をし、その履歴を閲覧できる |
| FR-POP-08 | **[必須]** v1 の規模: 人口 3,000〜10,000人相当、地区4〜6、追跡人物30〜80人 |
| FR-POP-09 | **[任意]** 出生・死亡・世代交代（v1 は年齢加算と引退のみで可） |

### 3.5 チーム（FR-TEAM）

| ID | 要件 |
|---|---|
| FR-TEAM-01 | **[必須]** チームは競技力・連携・所有/運営方式・利用権と契約・出場予定と疲労・育成環境・経済活動への関与を持つ |
| FR-TEAM-02 | **[必須]** 運営方式は「私有／店舗常駐／住民共同／公共／代理業」を区別し、**所有・運営・費用負担・利用機会を別属性として**扱う（concept §21-5） |
| FR-TEAM-03 | **[必須]** 代表活動（合宿・大会）は、選手の所属先チームの稼働に影響する |
| FR-TEAM-04 | **[必須]** チームの出場余力は疲労と人数で決まり、枯渇すると決済・大会に参加できない |

### 3.6 経済（FR-ECO）

concept §8 が詳細設計へ送った4項目を、v1 で**確定させる**。

| ID | 要件 |
|---|---|
| FR-ECO-01 | **[必須]** **現カバの受け渡し**: 商品・サービスは勝敗にかかわらず引き渡される。勝敗が決めるのは消費者側の支払負担の倍率（勝利=軽減、敗北=加重）。双方が時間と疲労を必ず消費する |
| FR-ECO-02 | **[必須]** **カード利用の換算**: 利用時に負担 (Obligation) を K建てで累積し、週末大会での清算力（チーム戦力 × 出場枠 × コンディション）と突き合わせる |
| FR-ECO-03 | **[必須]** **清算不足の扱い**: 不足分は繰越し、利用枠を縮小する。回復手段を最低2系統用意する（労務による直接清算／公的・共同体による肩代わり） |
| FR-ECO-04 | **[必須]** **事業者の持続条件**: 店舗・生産者・カード組合は収支を持ち、赤字継続で縮小・閉店・枠縮小を起こす。無限の体力を持たない |
| FR-ECO-05 | **[必須]** 財・サービスの生産は労働（農業・製造・建設・医療・飲食・接客）からのみ生まれる。カバディの勝敗は生産を増やさない |
| FR-ECO-06 | **[必須]** GDP は新規生産された財・サービスの標準価値の合計。中間投入を重複計上せず、勝敗による所有移転を生産に数えない。主表示は標準価値固定の実質値 |
| FR-ECO-07 | **[必須]** 「どれだけ生産したか」と「誰が受け取れたか」を別々の指標として表示する |
| FR-ECO-08 | **[必須]** 医療・高齢・育児等で本人が戦えない場合の代替決済経路（代理チーム／保険／共同体／公的支援）を最低2種実装する |
| FR-ECO-09 | **[必須]** 経済取引・試合を全件描画しない。内部集計し、重要な事例のみ提示する |

### 3.7 町・地区（FR-TOWN）

| ID | 要件 |
|---|---|
| FR-TOWN-01 | **[必須]** 施設種別: 道場／住宅／学校／病院／食堂／店舗／交通／決済会場／託児所／選手寮 |
| FR-TOWN-02 | **[必須]** 施設は定員・運営人員要件・維持費・稼働状態を持ち、定員超過で受け入れを停止する |
| FR-TOWN-03 | **[必須]** 地区間の移動距離・交通整備状況が、通勤・通学・練習参加・決済参加の時間コストに反映される |
| FR-TOWN-04 | **[必須]** 施設は「誰が利用できるか」（利用権）を持ち、建てただけでは全員が利用できない |
| FR-TOWN-05 | **[必須]** 施設の整備が町の見た目に反映される |

### 3.8 予算編成（FR-BUD）

| ID | 要件 |
|---|---|
| FR-BUD-01 | **[必須]** 年に一度、固定日に必ず発生する。政策カードでスキップできない |
| FR-BUD-02 | **[必須]** 次年度の収入見込みと既存事業の継続費用を提示したうえで、分野別に配分する |
| FR-BUD-03 | **[必須]** 配分先: 教育・指導者育成／医療・回復支援／住宅・生活支援／交通・町の基盤／道場・競技施設／公共チーム・経済参加支援／代表強化／予備枠 |
| FR-BUD-04 | **[必須]** 予算配分だけでは事業は完成しない。実際の使途は日々の政策カードで決まる |
| FR-BUD-05 | **[必須]** 予算は K建ての枠であり、実行時点で必要な実資源（人員・物資・公共チーム稼働）が確保できるとは限らない。**枠と実資源を別々に判定する** |
| FR-BUD-06 | **[必須]** 継続費用が収入を超える配分を組める。その結果（赤字・事業停止）は翌年度に現れる |

### 3.9 世界大会・領地（FR-CUP）

| ID | 要件 |
|---|---|
| FR-CUP-01 | **[必須]** 年に一度、固定日に発生する |
| FR-CUP-02 | **[必須]** 大会前に、代表選考・状態確認・最終調整・**賭ける領地と最大損失の確認**を行う |
| FR-CUP-03 | **[必須]** 最大損失は大会前に必ず明示する。想定外の損失を発生させない |
| FR-CUP-04 | **[必須]** v1 では本拠地地区を賭けの対象外とする。一度の敗戦で運営基盤が消滅しない |
| FR-CUP-05 | **[必須]** 試合は自動進行し、プレイヤーは結果を見届ける。細かな競技操作を要求しない |
| FR-CUP-06 | **[必須]** 試合演出は出場選手の背景（出身地区・経歴・過去のニュース）を引用する |
| FR-CUP-07 | **[必須]** 大会結果で領地の所属が変わる。獲得した領地は住民・施設・契約・履歴を引き継ぐ |
| FR-CUP-08 | **[必須]** 領地の喪失により、そこに属した人物が他国代表になり得る |
| FR-CUP-09 | **[必須]** 対戦国は4〜8カ国。各国は簡易モデル（戦力・成長率・領地）で年次更新される |

### 3.10 国家ステータス（FR-STAT）

| ID | 要件 |
|---|---|
| FR-STAT-01 | **[必須]** 日次更新。常時表示: 大会までの日数／人口／GDP／利用可能予算と収支見込み／国民平均カバディ能力／代表チームの状態 |
| FR-STAT-02 | **[必須]** 詳細表示6分野（経済・生活・育成・競技・分配・財政）を concept §13 の指標で実装する |
| FR-STAT-03 | **[必須]** 各指標は推移グラフと内訳（地区別・集団別）を開ける |
| FR-STAT-04 | **[必須]** 思想ラベル・総合スコアを表示しない。隠れた総合点で採点しない（concept §17） |
| FR-STAT-05 | **[必須]** ステータスとニュースは同一の内部状態から生成する（二重管理しない） |

### 3.11 ニュース（FR-NEWS）

| ID | 要件 |
|---|---|
| FR-NEWS-01 | **[必須]** 出来事は原則ニュース形式で流す。モーダルなポップアップは年次イベントと致命的事象に限る |
| FR-NEWS-02 | **[必須]** 記事種別: 政策効果／事業進捗／選手の成長・移籍・引退／経済・生活問題／大会結果／地域の話題／どうでもいい日常記事 |
| FR-NEWS-03 | **[必須]** 見出しから関連する人物・施設・地区へ遷移できる |
| FR-NEWS-04 | **[必須]** 過去記事を日付・対象・種別で検索・閲覧できる |
| FR-NEWS-05 | **[必須]** 気になる記事を留め置ける（ピン） |
| FR-NEWS-06 | **[必須]** 政策の進行終了時に、その期間の主要記事が残る |
| FR-NEWS-07 | **[必須]** 同一の人物・施設・問題について続報を出す（発生→悪化→対応→結果の連鎖を同一スレッドで追える） |
| FR-NEWS-08 | **[必須]** 全記事を読まなくても、町・施設・人物の状態画面から問題を把握できる |
| FR-NEWS-09 | **[必須]** ゲーム上の重大性と報道の大仰さが一致しない記事を混ぜる |

### 3.12 ネガティブイベント（FR-NEG）

| ID | 要件 |
|---|---|
| FR-NEG-01 | **[必須]** concept §15 の15種を実装する |
| FR-NEG-02 | **[必須]** 各イベントに対応策を2つ以上用意する（唯一解を作らない） |
| FR-NEG-03 | **[必須]** 発生はニュースで流し、通常は政策進行を中断しない |

### 3.13 UI（FR-UI）

| ID | 要件 |
|---|---|
| FR-UI-01 | **[必須]** 画面構成: 中央=町/国の地図、上部=国家ステータスとカレンダー、下部=ニュース流、政策選択パネル |
| FR-UI-02 | **[必須]** 情報は3段階で提供する: ①何が起きているか ②誰・どこで ③なぜ起きたか・何が改善に関係するか |
| FR-UI-03 | **[必須]** 費用・期間・状態・目標を隠さない |
| FR-UI-04 | **[必須]** 地図を切り替えて地域差・領土変化を確認できる |
| FR-UI-05 | **[必須]** 1920x1080 を基準とし、1280x720 まで破綻しない |
| FR-UI-06 | **[必須]** マウス操作で全機能に到達できる。キーボードショートカットは補助 |
| FR-UI-07 | **[任意]** ゲームパッド対応 |

### 3.14 セーブ・ロード（FR-SAVE）

| ID | 要件 |
|---|---|
| FR-SAVE-01 | **[必須]** 手動セーブ（複数スロット）とオートセーブ（年次イベント直前・政策実行直前） |
| FR-SAVE-02 | **[必須]** セーブはシミュレーション状態を完全に含み、ロードで同一状態を復元する |
| FR-SAVE-03 | **[必須]** セーブにバージョン番号を持ち、非互換データは破壊せず明示的に拒否する |
| FR-SAVE-04 | **[必須]** セーブ／ロードは 1秒以内 |

## 4. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | **決定論**: 同一セーブ＋同一操作列 → 同一結果。浮動小数の非決定的並列縮約を持ち込まない |
| NFR-02 | **性能**: 1ティックの計算 ≤ 2ms（目標人口規模）。60日進行を体感待ち時間3秒以内に収める |
| NFR-03 | **描画**: 60fps を維持。時間進行中も UI が応答する（フレームを止めない） |
| NFR-04 | **起動時間**: 5秒以内 |
| NFR-05 | **メモリ**: 2GB 以下 |
| NFR-06 | **依存**: 実行にインターネット接続・外部サービスを要求しない。テレメトリを送信しない |
| NFR-07 | **データ駆動**: カード・イベント・ニュース文面・施設・バランス係数を外部データファイルに置き、再ビルドなしで調整できる |
| NFR-08 | **テスト可能性**: シミュレーション本体を描画から独立して実行・検証できる |
| NFR-09 | **可観測性**: 任意の指標について「なぜその値になったか」を内部ログから追跡できる（開発時デバッグ機能） |
| NFR-10 | **ローカライズ余地**: 表示文字列をコードに埋め込まない |

## 5. v1 スコープ外

以下は**作らない**。将来追加の余地だけ残す。

- マルチプレイ、オンラインランキング、クラウドセーブ
- 選手個々の試合中操作、リアルタイム競技パート
- 3D 表現（2D 見下ろし／俯瞰で実装する）
- Mod API、シナリオエディタ
- 音楽・効果音の作り込み（最小限のプレースホルダのみ）
- 出生・死亡による人口動態の完全シミュレーション
- 複数国を同時に内政シミュレーションすること（他国は簡易モデル）
- 実績・Steam SDK 統合
- 日本語以外の言語

## 6. 受け入れ基準（v1 完了判定）

concept §20「検証すること」を、測定可能な形に落とす。

| ID | 基準 | 判定方法 |
|---|---|---|
| AC-01 | 1年（360日）を最後まで進行でき、クラッシュ・停止しない | 自動プレイ（ランダム政策選択）10回連続完走 |
| AC-02 | 予算編成と世界大会が必ず定日に発生し、残日数が失われない | 自動テスト |
| AC-03 | ある政策の実行前後で、意図した指標が意図した時期に意図した符号で動く | 全20カードの回帰テスト（同一シードで A/B 比較） |
| AC-04 | 政策 → 生活 → 行動 → 育成 の因果を、UI上の3段階情報から追える | 手動チェックリスト |
| AC-05 | 「生活問題で練習できない → 政策で改善 → 参加増 → 成長 → 代表入り」の経路を通る事例が、1年プレイで1件以上発生する | 自動プレイ統計 |

| AC-10 | セーブ→ロード→続行で状態ハッシュが一致する | 自動テスト |
| AC-11 | 敗戦時の損失が事前提示の最大値を超えない | 自動テスト |

## 7. リスク

| リスク | 影響 | 対応 |
|---|---|---|
| 経済モデルが発散・破綻する（負担が無限に累積する等） | 致命的 | 収支の恒等式を不変条件としてテストで常時検証する。§3.6 を試作初期に確定する |
| 因果が長すぎてプレイヤーに伝わらない | 体験の根幹が崩れる | 情報3段階UI（FR-UI-02）と続報ニュース（FR-NEWS-07）を早期に実装して検証する |
| 変数を増やしすぎて調整不能になる | 開発停滞 | concept §21-11。判断に意味を生む変数のみ追加する。追加時は対応する政策とUI表示をセットで作る |
| 日次ノイズが政策効果を覆い隠す | 学習が成立しない | FR-SIM-09。ノイズ幅を明示パラメータとして持ち、信号対雑音比をテストで測る |
| 1年完走のボリュームが出ない | MVP の検証ができない | カード20枚・イベント15種を先に用意し、その後で深さを足す |
